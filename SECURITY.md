# Security Policy

## Supported versions

BeforeCode currently maintains the latest content on the default branch. Documentation releases may be tagged as the project matures.

## Reporting a vulnerability

Do not report security vulnerabilities in a public issue.

Use GitHub's private vulnerability reporting feature if it is enabled for this repository. Otherwise, contact the repository owner privately through their GitHub profile and include:

- A clear description of the issue
- Affected file, workflow, prompt, or example
- Reproduction steps or proof of concept
- Potential impact
- Suggested mitigation, if available

## Relevant security concerns

Examples include:

- Prompts or examples that encourage unsafe credential handling
- Cross-tenant access patterns in reference architectures
- Insecure authorization or approval patterns
- Secret leakage in example configuration
- Unsafe agent tool execution guidance
- Malicious links or contributed content

General documentation suggestions and non-sensitive correctness issues should use the normal issue tracker.

## Response

The maintainer will acknowledge credible reports when possible, assess impact, prepare a correction, and coordinate disclosure. Please allow reasonable time for remediation before public discussion.

## Scope note

BeforeCode provides planning templates and reference examples, not security certification. Users remain responsible for threat modeling, professional review, and testing appropriate to their own systems.
