# Documentation Tracks by Project Type

Use this as a starting recommendation, not a mandatory bureaucracy checklist.

## Small App or Portfolio Project

**Core:** Project Brief, PRD, UX Flows, Build Plan, QA Checklist, README.

Add TRD when authentication, backend data, deployment, or integrations become meaningful.

## SaaS Product

**Core:** Project Brief, Research, PRD, UX, TRD, Database, API, Permission Matrix, QA, Implementation, Deployment.

Add BRD, decision records, threat model, billing, retention, and incident planning for multi-tenant or paid production systems.

## CRM, ERP, or Operations System

**Core:** BRD, process research, PRD/SRS, roles and permissions, lifecycle/state rules, data migration, API/integrations, audit, QA, deployment.

Prioritize import/export, duplicates, ownership, archive/restore, reporting accuracy, and permission testing.

## AI Agent

**Core:** Project Brief, Research, PRD, TRD, explicit agent workflow, tool/permission plan, memory plan, database/API, threat model, evaluation plan, QA, implementation.

Prioritize human approval, prompt injection, least privilege, durable state, idempotency, evidence, cost limits, observability, and regression evaluations.

## E-Commerce or Marketplace

**Core:** Research, BRD/PRD, catalog/order/payment states, permissions, data, APIs/webhooks, fraud/security, QA, deployment, support and rollback.

Prioritize money representation, inventory consistency, payment idempotency, refunds, taxes, notifications, and reconciliation.

## Mobile Application

**Core:** PRD, UX flows, offline/network states, permissions, API, analytics/privacy, compatibility matrix, QA, store release plan.

Prioritize lifecycle, background behavior, deep links, notifications, device permissions, upgrades, and crash reporting.

## Open-Source Tool

**Core:** Project Brief, README, roadmap, architecture/decision records, tests, changelog, license, contributing, code of conduct, support, security policy, issue/PR templates.

Prioritize a five-minute first success, stable examples, compatibility, versioning, community expectations, and release notes.

## High-Risk or Regulated System

Use the full set plus professional legal/security/compliance review, formal traceability, threat modeling, data classification, incident response, disaster recovery, audit evidence, and approval records.

Templates do not replace qualified review.
