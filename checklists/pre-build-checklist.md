# Pre-Build Checklist

## Product Clarity

- [ ] Problem, target user, and value proposition are specific
- [ ] MVP, future scope, and non-goals are separated
- [ ] Critical journeys and acceptance criteria are approved
- [ ] Business rules, roles, and terminology are consistent
- [ ] Open questions that block architecture are resolved

## Experience

- [ ] Information architecture and critical UX flows exist
- [ ] Loading, empty, error, permission, and recovery states are defined
- [ ] Responsive and accessibility requirements are documented
- [ ] Destructive and high-impact actions have confirmation behavior

## Engineering

- [ ] Technical architecture and component boundaries are reviewed
- [ ] Data ownership, schema, migrations, and retention are planned
- [ ] API contracts, errors, idempotency, and versioning are documented
- [ ] Authorization is enforced outside the UI
- [ ] Reliability, observability, and performance targets exist
- [ ] Build-versus-buy decisions and dependencies are recorded

## Delivery

- [ ] Implementation phases and critical path are defined
- [ ] Environments, CI, deployment, and rollback are planned
- [ ] Test strategy and required test data are ready
- [ ] Owners, milestones, risks, and stop conditions are clear
- [ ] Required credentials/access exist without exposing secrets

## Final Gate

- [ ] Documents are approved as the source of truth
- [ ] Cross-document names and rules are consistent
- [ ] Accepted risks have owner and review date
- [ ] Team or AI coding agent has a bounded first build plan
